# census-postgres

SQL DDL for loading Census releases into PostgreSQL, one directory per release (`acs2024_5yr/`, `dec2020_pl94/`, …), plus generators in `meta-scripts/`.
It's part of Census Reporter. For the whole-system map see `../censusreporter/CLAUDE.md`. For the release runbook see `../census-api/DATA_UPDATES.md`.

## Two eras
- **Sequence-based (≤ acs2021)**: data split into "sequence" files, keyed by `stusab`+`logrecno`, with many generator scripts.
  `README.md` and `SCHEMA.md` describe this era and are **largely outdated** for current releases.
- **Table-based (acs2022+ and `acs2021_1yr_tables`)**: the Census now publishes one file per table. For each release directory:
  - `ACS<YYYY><N>YR_Table_Shells.txt`: downloaded from the Census, the input.
  - `create_tables.sql` (a `bNNNNN_moe` table per ACS table, estimate + `_moe` REAL columns, `geoid` FK to geoheader), `create_views.sql`
    (a `bNNNNN` view with estimates only), `drop_schema_tables.sql`. All three are generated by
    `python meta-scripts/build_table_based_sql.py <shells.txt> <outdir> <schema>`.
  - `create_geoheader.sql`: copied from the prior release by hand and edited (no `logrecno`).
- `meta-scripts/fix_geoids.py` converts Census 7-character geoid prefixes (`1600000US`) to Census Reporter's 5-character form (`16000US`), in place, during import.
  It also blanks sentinel "jam values" while rewriting: anything that parses as a number below `-100000000`.
- `meta-scripts/fix_jam_values.py` is the backstop, run against a schema after loading (`PGURI` or `PG_URL`). It nulls any REAL column
  below the same threshold, and the `03_import_*` scripts call it. It's idempotent. Jam values reaching the database is a recurring bug;
  see the verification step in `../census-api/DATA_UPDATES.md`.
- `meta-scripts/create_user_geo_tables.sql`: schema for census-api's user_geo feature.

## Conventions
- Generated SQL is committed. Regenerate it with the script rather than hand-editing.
- These files are consumed by `census-postgres-scripts/table_based/03_import_*.sh`, which `git clone`s this repo from GitHub on the EC2 box.
  **Changes have no effect on imports until they're pushed.** Ask before pushing.
